## 零、需求来源与总原则

### 0.1 需求来源
唯一需求来源：投标技术应答表「4. 多源数据融合处理软件平台授权」7 条（均已应答“无偏离”），原文截图见项目根目录两张 PNG。

### 0.2 总原则（开发全程遵守）
1. **最小化满足**：只做 7 条需求要求的功能，每个功能都要能对应到 R1~R7 中的某一条；不参照、不照搬 iMAP 线上平台的功能范围。
2. **最简单的技术方案**：一个前端（GoView 二开）、一个后端（Node.js 自研），**不用 Docker**，用安装脚本 + systemd 直接部署。不引入后台框架，账号权限自己写，够用即可。
3. **完全离线**：学校服务器**不能访问外网**。所有前端资源、底图、字体、运行时（Node、GDAL、ffmpeg）都打进离线安装包，运行时零外网请求。
4. **可验收**：每条需求都写明“验收演示步骤”（见第六章），开发完成的标准是演示能一次走通。

### 0.3 需求条款编号

| 编号 | 条款原文要点 |
|------|-------------|
| R1 | BS 架构，内置二维和三维引擎，零代码可视化编辑；大屏页面支持新建、预览、修改、复制、重命名、删除、拖拽排序、一键发布、一键取消发布 |
| R2 | 二维图表与三维场景整合；多源数据（GIS/物联网/数据库/视频）接入；一键部署 |
| R3 | 支持 200 种以上数据格式直连；2D&3D 无缝切换；团队协作完成项目管理 |
| R4 | 内置素材模板：模型素材、地图素材、二维素材、场景模板 |
| R5 | 所见即所得，拖拉拽 + 现有组件库快速搭建可视化大屏 |
| R6 | 图层树编辑界面，支持多图层集；可基于栅格、矢量、三维模型、360 街景、在线地图服务创建图层 |
| R7 | 教学资源：实训指导书、微课视频、多媒体课件 PPT；演示视频 ≥4 个，每个 ≥100 秒；每个 PPT ≥10 页 |

### 0.4 学校现场条件（已确认）
- 服务器**不能访问外网**
- 学校区域的数据由学校自己采集后**上传到平台**，格式为 **LAS 点云**
- GIS 服务：目前没有具体产品，图层创建时用“GIS 产品”下拉框列出我们支持的主流产品即可
- 摄像头：**直接对接 RTSP 地址**
- 物联网平台：**只对接 RESTful API**
- 数据源先做最小集

## 一、项目概述

### 1.1 项目愿景
给学校交付一套轻量、可离线私有化部署的 B/S 可视化大屏平台。师生不写代码，通过拖拽就能把二维图表、三维场景和多源数据组合成大屏并发布。

### 1.2 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 管理员 | 学校信息中心 / 实训室管理员 | 开通账号、维护公共素材与模板、部署运维 |
| 教师 | 课程负责人，通常是团队负责人 | 建团队、拉学生、建项目、发布模板 |
| 学生 | 团队成员 | 在团队项目里协作搭建大屏、接入数据、发布成果 |
| 访客 | 不登录 | 查看已发布的大屏 |

### 1.3 业务主流程
```
管理员开通账号（单个/CSV 批量）→ 教师创建团队并添加成员 → 成员新建大屏（空白或从模板）
→ 拖拽图表/三维场景/视频组件 → 三维组件里编辑图层树、加载学校点云和 GIS 服务 → 图表绑定数据集
→ 预览 → 一键发布（生成访问链接）→ 需要时一键取消发布
```

## 二、技术方案

### 2.1 总体架构（无 Docker，两个 systemd 服务）
```
 浏览器 ──▶ vis-platform 服务（Node.js 进程，端口 80）
            ├─ 静态资源：GoView 前端（含管理页）/ Cesium 资源 / 底图瓦片 / 上传文件
            ├─ /api/**   ：账号、项目、团队、素材、数据集、数据文件
            ├─ /open/**  ：已发布大屏读取、数据集出口（免登录）
            └─ 内置 GDAL + py3dtiles 命令行（格式识别、转换、切片、点云转 3D Tiles）
          数据：/data/vis-platform/app.db（SQLite） + /data/vis-platform/files（文件）
 视频：vis-platform 按需拉起 ffmpeg 子进程，RTSP → HTTP-FLV（只转封装不转码），同一路摄像头多人观看共用一个 ffmpeg
```

### 2.2 技术选型

| 层 | 选型 | 用途 | 协议（已核实） |
|----|------|------|------|
| 前端（唯一） | **GoView `master-fetch` 分支**（Vue3 + Naive UI + ECharts） | 大屏编辑器 + 项目列表；管理页（用户、团队、素材、数据集、数据文件）也加在这个应用里 | MIT |
| 二三维引擎 | CesiumJS | 三维场景组件、2D/3D 切换、各类图层 | Apache 2.0 |
| 360 街景 | Photo Sphere Viewer | 全景图查看 | MIT |
| 视频播放 | hls.js + mpegts.js | HLS / HTTP-FLV | Apache 2.0 |
| 后端 | Node.js 20 + TypeScript + Fastify + Prisma | 业务接口 + 静态资源服务 | MIT |
| 数据库 | SQLite（Prisma 管理） | 业务数据。以后要换成 PostgreSQL，只改 Prisma 的 provider | 公有领域 |
| 鉴权 | JWT + bcrypt，三个角色写死在代码里 | 登录与权限 | — |
| 格式转换 | GDAL（micromamba 可移植环境，随安装包提供） | 200+ 栅格/矢量格式 → GeoJSON / XYZ 瓦片 | MIT |
| 点云转换 | py3dtiles | LAS/LAZ 点云 → 3D Tiles | Apache 2.0 |
| 视频转流（必选） | ffmpeg 静态二进制（后端按需拉起子进程） | 摄像头 RTSP → HTTP-FLV | LGPL/GPL（作为独立程序调用，随包附源码获取说明） |
| 部署 | 离线 tar.gz 安装包 + `install.sh` + systemd（**不用 Docker**） | 一键部署 | — |

> 不再使用 Snowy（小诺）：只需要三个固定角色的权限，自己写大约几百行代码，比引入一整套后台框架简单；同时也不用处理它的授权条款问题。

### 2.3 关键设计决策（已拍板）
- **D1 不单独做三维编辑器**：三维能力全部做成 GoView 里的一个「三维场景」组件，图层树放在这个组件的配置面板里。一个编辑器就同时覆盖 R1、R2、R5、R6。
- **D2 主引擎用 Cesium，不用 Three.js**：R3 的 2D&3D 切换和 R6 的栅格、矢量、在线地图服务都需要 GIS 能力，Cesium 原生支持。三维模型的编辑通过“拾取定位 + 属性面板数值调整”实现。
- **D3 数据接入只有一个入口**：HTTP（RESTful，用于物联网平台）、MySQL 统一抽象成「数据集」，对外只暴露 `GET /open/dataset/{id}/data` 一个接口，GoView 组件复用自带的「动态请求」去拉。后端每种类型就是一个 provider，由注册表统一分发。
- **D4 “格式直连”的实现方式**：上传任意 GDAL 支持的格式，后端自动识别后转成 Cesium 能直接加载的格式（矢量转 GeoJSON，栅格转 XYZ 瓦片）。
- **D5 离线底图与学校数据**：内置 Cesium 自带的 NaturalEarthII 全球低精度底图作为兜底；学校采集的 LAS 点云上传后转成 3D Tiles，以三维模型图层加载（走 F014 → F010）。
- **D7 视频只对接 RTSP**：浏览器不能直接播放 RTSP，所以由后端按需拉起 ffmpeg 子进程转封装为 HTTP-FLV（不再单独部署流媒体服务）；用户只需要填 RTSP 地址，转流对用户透明。
- **D6 一个前端、一个后端、不用 Docker**：管理页并入 GoView 应用；后端同时负责托管静态资源，不需要单独的 Nginx；所有运行时都以免安装二进制形式随包提供，由 systemd 管理。

## 四、功能详情

### F001: 账号与权限（自研）
- **用户故事**：作为管理员，我要给师生开通账号、分配角色，师生登录后只能看到自己有权限的功能。
- **验收标准**：
  - [ ] 用户名 + 密码登录（bcrypt 加密存储），返回 JWT，有效期 7 天
  - [ ] 三个固定角色：`admin` / `teacher` / `student`，权限按第五章权限矩阵执行；前端按角色显示或隐藏菜单，**后端每个接口都要校验角色**
  - [ ] 管理员可以单个新建账号，也可以上传 CSV（工号或学号、姓名、角色）批量导入；导入结果逐行显示成功或失败原因
  - [ ] 重置密码、禁用账号；首次登录强制修改密码
  - [ ] 登录失败 5 次锁定 10 分钟
- **技术备注**：鉴权做成一个 Fastify 插件，路由声明 `roles` 后自动校验；守卫测试遍历全部路由，没有声明 `roles` 或 `public` 的直接报错。

### F002: GoView 前端改造
- **验收标准**：
  - [ ] 基于 `master-fetch` 分支，把接口地址改为自研后端，统一前缀 `/api`；登录页换成我们自己的
  - [ ] 新增管理页：用户、团队、素材库、数据集、数据文件，统一放在项目列表页左侧菜单里
  - [ ] **离线化**：全面检查 GoView 依赖的 CDN 资源（字体、图标、地图 GeoJSON、示例 iframe 等），全部改成本地资源；断网环境下浏览器 Network 面板里没有外网请求
- **关联接口**：以 GoView `master-fetch` 分支 `src/api/path/` 下已定义的接口为准，后端照着实现；缺的接口（复制、重命名、排序）按同样的风格补上。

### F003: 大屏页面 CRUD
- **验收标准**：
  - [ ] 新建（空白 / 从模板）、修改（进入编辑器）、复制（复制出一份“原名-副本”）、重命名、删除（需二次确认，逻辑删除）、预览
  - [ ] 列表只显示当前用户有权限的项目：本人的 + 所在团队的；管理员能看到全部

### F004: 大屏页面拖拽排序
- **验收标准**：
  - [ ] 项目列表里卡片可以拖动排序，松手后自动保存，刷新后顺序保持
- **技术备注**：`project.sortOrder` 字段；接口 `PUT /api/project/sort`，传入 id 数组。

### F005: 一键发布 / 一键取消发布
- **验收标准**：
  - [ ] 列表卡片和编辑器里都有“发布 / 取消发布”切换按钮，点一次就生效
  - [ ] 发布后生成访问链接，不登录也能访问
  - [ ] 取消发布后，这个链接返回“未发布”提示页

### F006: GoView 拖拽编辑与组件库
- **验收标准**：
  - [ ] GoView 自带的图表、信息、列表、小组件、图片、图标几类组件都能拖进画布、能配置、能保存、能预览

### F007: 三维场景组件
- **用户故事**：作为用户，我从组件库把「三维场景」拖进大屏，跟柱状图等二维图表并排摆放，组成一个二三维融合的大屏。
- **验收标准**：
  - [ ] 组件库里新增“三维”分类，下面有一个「三维场景」组件
  - [ ] 拖进画布后显示 Cesium 地球（离线底图），尺寸和位置跟着画布拖拽缩放
  - [ ] 组件配置（图层树、相机初始视角、显示模式）随项目一起保存，预览和发布页按原样还原
  - [ ] 不使用 Cesium Ion：`baseLayer: false`、关闭 geocoder 和 baseLayerPicker，运行时没有外网请求
- **技术备注**：按 GoView 自定义组件规范放在 `packages/components/` 下；Cesium 静态资源放到 `/static/cesium`。

### F008: 2D&3D 无缝切换
- **验收标准**：
  - [ ] 三维组件上有“2D / 2.5D / 3D”切换按钮，切换有过渡动画，切换后图层不丢失；可以设置默认模式
- **技术备注**：Cesium `SceneMode` + `morphTo2D / morphToColumbusView / morphTo3D`。

### F009: 图层树编辑
- **验收标准**：
  - [ ] 三维组件配置面板里有图层树：图层集（分组）→ 图层，两级
  - [ ] 支持新建、重命名、删除图层集；图层支持新增、删除、拖拽排序（包括跨图层集）、显隐勾选、透明度调节、“定位到图层”
  - [ ] 多个图层集可以同时存在，整组勾选时整组显隐
- **数据结构**：图层树以 JSON 形式存在组件 option 里，不单独建表：
  ```json
  { "layerSets": [ { "id": "", "name": "", "visible": true,
      "layers": [ { "id": "", "name": "", "type": "raster|vector|model|service|panorama",
                    "source": {}, "visible": true, "opacity": 1, "style": {} } ] } ] }
  ```

### F010: 图层类型
| 类型 | 创建方式 | 实现 |
|------|---------|------|
| 栅格 | 从“数据文件”里选一个已切片的栅格（如 GeoTIFF），或者从素材库选地图素材 | `UrlTemplateImageryProvider` |
| 矢量 | 从“数据文件”里选一个已转换的矢量 | `GeoJsonDataSource`，可配填充色、边线色、点图标 |
| 三维模型 | 从素材库选 glTF/GLB，或者选一个已转换的 3D Tiles（**学校的 LAS 点云走这里**） | `Model.fromGltfAsync` / `Cesium3DTileset`；点云可调点大小、按高程或强度着色 |
| 在线地图服务 | 先在“GIS 产品”下拉框里选产品，再填服务地址和图层名 | 按下面的映射表，选择对应的 ImageryProvider |
| 360 街景 | 在地图上放一个点并绑定一张全景图 | 点击点位后弹出 Photo Sphere Viewer |

**“GIS 产品”下拉框（下拉框旁边显示“平台支持以下 GIS 产品发布的服务”）：**

| 下拉选项 | 实际使用的协议 |
|---------|--------------|
| ArcGIS Server / ArcGIS Enterprise | ArcGIS MapServer（REST）、WMS、WMTS |
| GeoServer | WMS、WMTS |
| SuperMap iServer（超图） | WMS、WMTS |
| MapGIS IGServer（中地数码） | WMS、WMTS |
| 天地图（内网离线部署版） | WMTS |
| 通用 OGC 服务 | WMS、WMTS |
| 通用瓦片服务 | XYZ（`{z}/{x}/{y}`） |

> 实现上只有 4 种 Provider（ArcGIS MapServer / WMS / WMTS / XYZ），下拉框只决定可选协议和参数模板，不为每个产品单独写代码。产品列表写在一张配置表（前端常量）里，以后加产品只改配置。

- **验收标准**：五种类型各建一个图层，都能在图层树里正常显示、显隐和删除；用 GeoServer 发布一个 WMS 测试服务，再用一个 XYZ 瓦片目录，各接通一次。

### F011: 三维模型摆放编辑（P1）
- **验收标准**：
  - [ ] 选中模型图层后点“拾取位置”，在地图上点一下就把模型放到该点
  - [ ] 属性面板可以调经度、纬度、高度、朝向、俯仰、翻滚、缩放比例，改动实时生效

### F012: 数据集（多源数据接入，最小集）
| 类型 | 配置项 | 行为 | 现场用途 |
|------|--------|------|---------|
| RESTful API | URL、方法（GET/POST）、请求头、请求体、JSON 取值路径（可选，例如 `data.list`） | 后端代理请求，按取值路径截取后返回 JSON | 对接学校物联网平台 |

- **验收标准**：
  - [ ] 数据集管理页：新增、编辑、删除，并提供“测试连接 / 预览数据”
  - [ ] 统一出口 `GET /open/dataset/{id}/data`；GoView 图表的“动态请求”填这个地址并设置轮询间隔，就能实时刷新
  - [ ] MySQL 只放行单条 SELECT；密码不能明文回显

### F013: 视频组件
- **验收标准**：
  - [ ] 组件库里新增「视频」组件，配置项：RTSP 地址、是否自动播放、是否静音

  - [ ] 拉流失败（地址错误、摄像头不在线）时组件上显示明确的错误提示

## 九、服务器配置建议（用于向学校提要求）

### 9.1 估算依据
- **三维渲染在浏览器端完成**，服务器只负责提供文件和接口，**不需要显卡**
- 服务器的主要负载：点云转换和栅格切片（吃 CPU 和内存）、静态文件下发（吃磁盘 IO）、摄像头转流（每路约占 2~5 Mbps 带宽，转封装不转码，CPU 占用低）
- 存储大头是学校的 LAS 点云：一个校区通常是几 GB 到几十 GB，转成 3D Tiles 后体积和原始文件差不多，加上原始文件要按 2 倍预留
- 并发量按一个机房 50~100 人同时使用估算

### 9.2 服务器

| 项目 | 最低配置 | 推荐配置 |
|------|---------|---------|
| CPU | 4 核 | 8 核及以上 |
| 内存 | 16 GB | 32 GB |
| 系统盘 | 100 GB SSD | 200 GB SSD |
| 数据盘 | 500 GB SSD | 1 TB SSD（点云数据多时选 2 TB） |
| 显卡 | 不需要 | 不需要 |
| 网络 | 千兆内网 | 千兆内网 |
| 操作系统 | Linux x86_64 或 arm64（Ubuntu 22.04 / 麒麟 V10 / openEuler 等） | 同左 |
| 软件 | 无需预装任何软件（不需要 Docker），只需要 systemd、root 权限，glibc ≥ 2.28 | 同左 |
| 端口 | 对内网开放 80（或 443） | 同左 |
| 网络访问 | 能访问学校摄像头的 RTSP 地址（默认 554 端口）、物联网平台接口、业务数据库 | 同左 |

### 9.3 客户端（教室电脑、大屏展示端）
- 浏览器：Chrome 或 Edge 最新版（不支持 IE），需要支持 WebGL2
- 内存 8 GB 及以上，有独立显卡或较新的集成显卡，分辨率 1920×1080 及以上
