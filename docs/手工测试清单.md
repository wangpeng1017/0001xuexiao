## 6. 团队协作、素材与模板（F015~F018，R3 R4）
### 6.1 账号准备
1. admin 登录 → 用户管理 → 新建教师账号 `teacher01`、学生账号 `student_a`、`student_b`（角色分别选教师/学生）。
2. 确认新账号首次登录需改密。

### 6.2 菜单与可见性
1. admin 登录：侧边栏应为「项目（全部项目、模板库）→ 数据 → 协作与素材（团队管理、素材库）→ 用户管理」。
2. teacher 登录：能看到「团队管理」「素材库」，看不到「用户管理」。
3. student 登录：能看到「模板库」「素材库」，看不到「团队管理」「用户管理」。
4. 项目列表筛选：admin 能看到「全部」；teacher/student 看不到。

### 6.3 团队协作
1. teacher 登录 → 团队管理 → 新建团队「三维实训团队」。
2. 详情抽屉 → 添加成员 → 搜索 `student` → 选择学生 A、B → 添加；成员列表出现三人，teacher 标记为负责人。
3. （可选）更换负责人为学生 A → 列表负责人变化；再换回 teacher。
4. 学生 A 登录 → 项目列表 → 新建 → 归属选择「团队：三维实训团队」→ 空白 → 编辑器打开；添加任意组件并点击保存。
5. 学生 B 登录 → 项目列表 → 切到「团队」→ 选择团队 → 能看到 A 的项目，卡片显示团队名、最后修改人 A、修改时间；打开编辑。
6. 双窗口冲突：A 修改并保存；随后 B 修改并点击保存 → 弹出「保存冲突」，提示“该项目已被 学生 A 于 … 修改”，有「覆盖保存」「重新加载」。
7. 点「覆盖保存」→ 提示“已覆盖保存”，B 的修改生效；如点「重新加载」→ 内容回到 A 最新版本，且 B 的未合并修改被丢弃。
8. 学生 B 卡片菜单中不应出现「设为模板」；删除按钮应返回无权限（若前端展示）。
9. （可选）teacher 删除团队需二次确认；删除后学生 A/B 的团队筛选里不再有该项目，项目仍归 A 个人所有。

### 6.4 模板
1. teacher 登录 → 项目列表（团队范围）→ 学生 A 的项目卡片菜单 → 设为模板 → 选择「校园三维」→ 成功。
2. 模板库页面（菜单「项目 → 模板库」）→ 出现「校园三维」分组及该模板卡片。
3. student B 登录 → 模板库 → 使用此模板 → 输入项目名、归属选个人 → 创建并打开编辑器（新窗口），内容与模板一致、未发布、卡片无「模板」标记。
4. teacher 在项目卡片点「取消模板」→ 模板库该卡片消失。
5. admin/teacher 在项目列表「全部/团队」范围可设置模板；student 卡片无此菜单。

### 6.5 素材库
1. admin 登录 → 素材库 → 上传模型（`.glb`，或含 `.gltf` 的 zip）→ 成功；卡片在数秒内出现缩略图（三维截帧）。
2. 上传地图 `.geojson` 或瓦片 zip（`0/0/0.png` 结构）→ 卡片出现在「地图」页签。
3. 上传二维素材（png/jpg 等）→ 「二维」页签显示原图缩略图。
4. 用 student 登录：上传弹窗的可见范围只有「私有」，无「公共」；私有素材只有本人可见；admin 公共素材所有账号可见。
5. 删除素材有二次确认；非创建者/非 admin 删除应失败。
6. 上传非法扩展名（如 `.obj`、`.txt`）应提示失败；上传带 `../` 路径的 zip 应被拒绝。

### 6.6 编辑器图片组件选用二维素材
1. 打开任意项目编辑器 → 添加「图片」组件 → 右侧配置「路径」下出现「从素材库选择」。
2. 点击 → 弹出素材选择器，展示 `image2d` 公共 + 本人私有素材；搜索框可按名称过滤。
3. 选中一张 → 配置路径自动填入 `/files/materials/<id>/<文件名>` → 画布图片立即显示。
4. 保存后刷新编辑器，图片仍正常显示（同源 `/files` 代理）。

### 6.7 预置素材与场景模板（F018）
> 首次启动时自动导入 20 个公共素材（素材库可见）和 3 个模板。

1. **模板库可见性**
   - 启动系统并用 admin 登录 → 打开「项目 → 模板库」。
   - 确认出现 3 个模板：智慧校园三维总览（校园三维）、实训设备监控（设备监控）、教学数据统计（数据统计）。
   - 确认 3 张封面正常显示（非裂图），标题/色块与模板内容一致。
2. **逐模板新建**
   - 用每个模板执行「新建项目」，名称任意；3 次均成功，生成的项目不再是模板、内容为深拷贝（后续修改不影响模板）。
3. **编辑器加载**
   - 打开新建项目，观察无报错弹窗、无组件缺失/空白（教学模板 25 个组件、设备模板 16 个、校园模板 8 个）。
   - 检查每个组件能在右侧配置面板正常打开（文字/柱状图/折线图/饼图/表盘/表格/图片/数字卡片/边框/摄像头/三维场景）。
4. **校园三维模板**
   - 三维场景可渲染，图层树含「校园底图 / 校园要素 / 三维模型 / 360 街景」；
   - 底图为校园离线瓦片；建筑/道路/POI 三个矢量可见；教学楼 + 2 棵树模型位置正确；
   - 点击街景点可打开 `panorama-demo.jpg` 全景；
   - 相机初始视角落在 116.30~116.32 / 39.99~40.01。
5. **设备监控模板**
   - 温度趋势折线图有数据、表盘显示 68%、设备列表 6 行；
   - 摄像头组件显示“请配置 RTSP 地址”占位；在配置面板填写可用 RTSP 并连接后返回 streamId（无摄像头环境可仅验证留空占位）；
   - camera/server/alarm 图标显示正常。
6. **教学数据统计模板**
   - 4 个数字卡片正常滚动计数；2 柱 / 2 折线 / 1 饼图有静态数据；
   - 打开「资源访问趋势」的数据配置，确认请求方式为“动态”、请求地址为空；按备注粘贴接口地址后可取数；
   - 画布备注与项目备注均可见“绑定数据集后在此粘贴接口地址”。
7. **预览/发布**
   - 三个项目分别进入预览，布局 1920×1080 正常缩放，背景图、图表、三维场景、封面均正常；无控制台报错。

## 7. 部署（F019，R2）
> 需要一台 Linux 服务器（x64 或 arm64），按 `deploy/README.md` 操作。
| # | 操作 | 预期 |
|---|---|---|
| 7.1 | 在联网机器上执行 `bash deploy/build-package.sh --arch x64 --version 1.0.0` | 生成 `vis-platform-1.0.0-linux-x64.tar.gz` 和对应的 sha256 文件 |
| 7.2 | 把安装包拷到**断网**的 Linux 服务器上，解压后执行 `sudo ./install.sh` | 10 分钟内完成，打印访问地址和管理员初始密码 |
| 7.3 | 重启服务器 | 服务自动启动 |
| 7.4 | 执行 `sudo ./install.sh --upgrade` | 数据和配置保留，服务正常 |
| 7.5 | 执行 `backup.sh`，再执行 `restore.sh` | 数据恢复到备份时的状态 |
